# RentFlow MVP — Outcome Tracker

- [ ] **Working product, stack, roles, and isolation** — Build a working MVP, not a mockup, for small landlords and property managers in Kenya. Backend: Go 1.22+, chi router, PostgreSQL, sqlc for queries, golang-migrate for migrations, JWT auth (access + refresh tokens), bcrypt for passwords, structured logging (slog), config via environment variables. Frontend: Next.js (App Router) + TypeScript, Tailwind CSS, shadcn/ui, TanStack Query, React Hook Form + Zod. Mobile-first, responsive, installable as a PWA. Infrastructure: Docker + docker-compose (api, web, postgres), Makefile for common commands, GitHub Actions CI (lint, test, build for both apps). Landlord/Agent manages properties, units, tenants, payments, reports. Tenant logs in to see their balance, payment history, receipts, and pay via M-Pesa. All data must be isolated per landlord account (multi-tenant design). **Partial:** the working API and responsive frontend exist; generated sqlc code is currently used for Free-plan unit counting while most other queries use pgx directly. Compose, Docker, Makefile, and CI files exist, but Docker execution was unavailable in this environment.

- [x] **Authentication and account access** — Provide register, login, refresh, logout, and password reset flow (email can be stubbed). Use the requested JWT access + refresh tokens and bcrypt passwords. Enforce role-appropriate access for Landlord/Agent and Tenant; isolate all data per landlord account. **Evidence:** API smoke flows pass; final Preview session cookies were verified as `Secure; SameSite=None`.

- [x] **Properties, units, tenants, and leases** — Properties and units have CRUD. A unit has a code (e.g. "A12"), monthly rent, and status (vacant/occupied). Add tenants, assign them to a unit, and record lease start date, rent amount, due day of month, and deposit. **Evidence:** API smoke covered account-scoped CRUD, tenant/lease fields, and the frontend tenant-password and unit-status form contract was corrected.

- [x] **Recurring invoices and ledger/reconciliation** — A scheduled job generates automatic monthly invoices on each lease's billing cycle. Provide a per-tenant ledger (invoices vs payments), running balance, and overdue list with days overdue. Support partial payments and overpayments, carrying credit forward. **Evidence:** invoice generation, overdue-day counts, partial allocation, and carried credit passed the isolated API smoke suite; the daily scheduler and idempotent period rules are implemented.

- [ ] **Daraja M-Pesa collection, callbacks, and exception review** — Integrate Safaricom Daraja API. Provide STK Push so a tenant can pay from the app. Provide C2B Paybill validation and confirmation URLs so payments made directly to the Paybill are captured. Use the unit code as the account reference to auto-match payments to tenants. Unmatched payments go to a "needs review" queue where the landlord can assign them manually. Callbacks must be idempotent (never double-record the same M-Pesa transaction code). Use the Daraja sandbox by default; all credentials come from environment variables. Use the sandbox API at `https://sandbox.safaricom.co.ke`. The supplied real sandbox values must be stored ONLY in `backend/.env`, and `backend/.env` must be listed in `.gitignore`. `backend/.env.example` must contain the variable names with placeholder values such as `your_consumer_key_here`, never real credential values. The supplied `MPESA_CALLBACK_URL` is to be set to the user's ngrok HTTPS URL later plus `/api/v1/mpesa/stk-callback`. **Partial:** synthetic callback tests verify shortcode, production callback-token enforcement, STK amount/phone matching, idempotency, and account-linked manual assignment. C2B callbacks with no unique safe unit match remain unassociated to avoid cross-landlord exposure and therefore cannot enter a landlord queue until account-specific Paybill mapping is implemented. No live STK prompt or public callback was triggered; the production database and public ngrok callback are not configured.

- [x] **SMS reminders and receipts** — Send SMS reminders before due date, on due date, and when overdue, plus payment receipts. Use a provider interface with an Africa's Talking implementation and a mock for local development. **Evidence:** scheduler, provider interface, mock, receipt paths, and Africa's Talking recipient-status parsing are implemented and covered by Go tests; no external SMS was sent.

- [x] **Landlord dashboard** — Show expected vs collected this month, collection rate, arrears total, vacant units, and recent payments. **Evidence:** account-scoped dashboard keys and response values passed the isolated API smoke suite.

- [x] **Reports and CSV export** — Provide a monthly collection report and an arrears report, both exportable as CSV. **Evidence:** both account-scoped CSV downloads passed the isolated API smoke suite.

- [x] **Subscription-ready unit limits** — Add a plans table and enforce a unit limit per landlord plan (e.g. Free up to 5 units). Do not implement billing; only implement the limit enforcement. **Evidence:** Free-plan creation succeeded through five units and rejected the sixth; no billing flow is implemented.
